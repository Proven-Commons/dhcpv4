## Wireshark

TShark (Wireshark) 4.2.2 (Git v4.2.2 packaged as 4.2.2-1.1build3). Each message the parts above fed the tool (the request lines with no codes and the malformed request lines are not messages) is written by the harness as the UDP payload of an Ethernet/IPv4/UDP frame, from port 68 to port 67, or from 67 to 68 when its op byte is 2, into a pcap file, and dissected in batches of 500 by `tshark -n -r <file> -T json -x` with an empty personal configuration. For each message the tool takes, the harness compares op, htype, hlen, hops, xid, secs, flags, ciaddr, yiaddr, siaddr, giaddr, chaddr, sname, file and the cookie (each as Wireshark shows it, and read at the offset SPEC.md gives), every option's code, length and value bytes in order, the end option and what follows it, and the message type. For every message it checks whether Wireshark marks the frame Malformed Packet, where it stops, and each expert error it reports.

Each such fault is matched with one the harness finds in the message's bytes by following the checks of Wireshark 4.2.2's DHCP/BOOTP dissector (`WsModel` in tests/run_tests.py, written from epan/dissectors/packet-dhcp.c and get_dns_name in packet-dns.c at tag v4.2.2): the same exception at the same option, the same number of errors in the same option. A fault Wireshark reports that the harness does not find is a failure, and so is one the harness finds that Wireshark does not report, except in the options whose checks it does not follow in full (122, the CableLabs client configuration sub-options, followed only as far as their lengths).

A message the tool takes agrees when Wireshark shows every compared field as the tool reads it and reports no fault. A message the tool turns away agrees when Wireshark stops with an exception at a rule the tool turns it away for: short, the message is shorter than the fixed fields and the cookie, and Wireshark stops with an exception before any option; overrun, an option runs past the end of the message, and Wireshark stops with an exception at that option; code-last, the last byte is an option code with no length byte, and Wireshark stops with an exception there; 53-empty, option 53 has length 0, and Wireshark stops with an exception reading the type byte; or when there is no payload at all. Any other difference is a failure unless the harness finds its reason in the message itself, under one of the named differences below; for a message the tool turns away, each rule it breaks that Wireshark's dissection reaches must show in Wireshark's own reading. The list is computed by this run, with the number of messages under each; a message can fall under more than one.

The tool takes 1918 of the messages: Wireshark agrees on 635, differs only under named differences on 1283, and fails on 0. The tool turns away 2172: Wireshark agrees on 1071 (short), 127 (overrun), 120 (code-last), 97 (53-empty), 6 (no payload to dissect), differs only under named differences on 751, and fails on 0.
